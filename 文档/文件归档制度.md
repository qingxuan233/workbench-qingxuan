# 文件归档制度（File Archiving Policy）

> **生效**：2026-11-07 · **适用范围**：本仓库全部「非场景」文件（文档 / 脚本 / 产物 / 配置）。
> 场景本身的内容（`外壳/scenarios/*`、`引擎数据/.dsh/场景记忆/`、面板渲染器）不在本制度内，按
> [记忆约定.md](../12-源码照搬/说明/记忆约定.md) 与 `场景校验.mjs` 管。
> **判据（本制度靠代码守，不靠自觉）**：
> `node 12-源码照搬\工具\结构校验.mjs --check` → 期望 `✓ 结构与链接全部通过`。

---

## 0. 三条总则

1. **根目录只放「入口与运行必需」**：文档一律进 `文档/`，历史文档进 `文档/归档/`，本机产物进 `_本机产物/`。
2. **一个文件只有一个家**：先定位置再写内容；**同一内容不存两份**——复制出来的副本一定会有一份先过期。
3. **过期不删除，搬家再登记**：过期文档 `git mv` 进 `文档/归档/` + 顶部加横幅 + 在索引登记；
   本机产物**不入库**，也不许混进 `文档/` 冒充现行文档。

## 1. 目录分区（唯一口径）

| 区 | 路径 | 放什么 | 不放什么 | 入库 |
|---|---|---|---|---|
| **入口区** | `README.md`、`AGENTS.md`、`LICENSE` | 两个人/机入口 + 许可证 | 任何正文文档、任何产物 | ✅ |
| **运行区** | `启动工作台.bat/.vbs`、`同步上游.mjs`、`cordis.patch.optimized.yml`、`preset-*.optimized.patch.yml` | 启动器、仓库级维护脚本、本机补丁 | 文档、一次性脚本 | 补丁 ❌ 其余 ✅ |
| **应用区** | `12-源码照搬/`（代码 + `说明/`） | 外壳源码、工具、场景模板（占位）、应用文档 | 跨板块文档（放 `文档/`） | ✅ |
| **知识区** | `00-核心机制/` … `13-公开情报/`、`模板/`、`配图/` | 编号知识板块、模板、图片素材 | 现行口径文档（放 `文档/`） | ✅ |
| **文档区** | `文档/`（含 `归档/`） | 跨板块的人读文档、历史归档 | 代码、产物、日志、截图 | ✅ |
| **本机产物区** | `_本机产物/` | 本机分析、审计、探针、一次性报告 | 任何要入库的东西 | ❌ 整目录忽略 |
| **运行时数据区** | `12-源码照搬/引擎数据/.dsh/`、`12-源码照搬/外壳/data/`、`_临时/` | 会话/凭据/工作区/日志/缓存/截图 | 源码与文档 | ❌（`.gitignore` 管） |
| **隐藏状态区** | `.git/`、`.githooks/`、`.acl-recovery/`、`.dsh-switchman/` | Git 内部与工具状态 | 手动维护的文档 | 按既有规则 |

> 运行时数据区与隐藏状态区的**忽略规则**在根 `.gitignore` 与 `12-源码照搬/.gitignore` 里，本制度不重复抄写；
> 只规定它们**不得**出现在 `git ls-files` 清单里（结构校验会查）。

## 2. 根目录白名单（结构校验会逐条比对）

**允许的根级文件**：

```
README.md   AGENTS.md   LICENSE   .gitattributes   .gitignore
启动工作台.bat   启动工作台.vbs   同步上游.mjs
cordis.patch.optimized.yml   preset-*.optimized.patch.yml   （本机补丁，已被 .gitignore 挡）
```

**允许的根级目录**：

```
.git/  .githooks/  .acl-recovery/  .dsh-switchman/
00-核心机制/ … 13-公开情报/   （编号板块，两位数字 + 中文名）
模板/  配图/  文档/  12-源码照搬/  _本机产物/
```

**⛔ 根目录不允许**：散落的 `*.md`（除两个入口）、`*.log` / `*.png` 截图 / `*.zip` 备份、`副本` / `最终版`、
一次性脚本、一次性报告、临时目录。

新增根级条目 = 同时改**本节 + `工具/结构校验.mjs` 的白名单**，两处必须一致，否则校验红。

## 3. 新文件落位决策树

按顺序问，命中即停：

1. **是代码 / 配置 / 脚本吗？** → `12-源码照搬/`（`工具/`、`外壳/scripts/`、`外壳/main/`）。
2. **是场景内容吗？**（场景 json、场景记忆、面板）→ `12-源码照搬/外壳/scenarios/`、`12-源码照搬/引擎数据/.dsh/场景记忆/`。
3. **是某个编号板块专属吗？** → 该板块目录（如 `02-会话定位与跟随/`），**不要放根**。
4. **是跨板块的人读文档吗？** → `文档/`（并在 [文档/README.md](README.md) 登记）。
5. **是本机分析 / 审计 / 探针 / 一次性报告吗？** → `_本机产物/<类型>/`。
6. **是运行日志 / 截图 / 缓存吗？** → 对应 `data/` 目录（已被忽略），按 §5 保留期清理。
7. **已经过期了吗？** → `文档/归档/`（按 §7 流程）。

> 兜底判据：**「它 3 个月后还有谁读？」** 没人读 → `_本机产物/` 或直接删；有人读 → `文档/`。

## 4. 命名规范

- 文档：`主题.md`；带时间结论用 `主题-YYYY-MM-DD.md`（与既有 `-2026-11-01` 一致）。
- **禁止** `最终版 / 新版 / 副本 / copy / old / 临时`——版本靠 git，不靠文件名。
- 编号板块：`NN-中文名`；新增板块顺延（14、15…），并同步根 `README.md` 的板块表。
- 本机产物：`_本机产物/<类型>/<YYYY-MM-DD>-<主题>/`（例：`_本机产物/审计/2026-11-07-整理后审计.md`）。
- 报告类前缀：`总报告-`（汇总结论）、`审计-`（独立核对）、`诊断-`（现象复现与修复）。
- 文件名不出现空格、制表符、`?*<>|`；目录名用中文（既有口径）。

## 5. 生命周期与保留期

| 类型 | 位置 | 保留期 | 到期处置 |
|---|---|---|---|
| 现行文档 | `文档/` | 长期 | 过期 → 按 §7 归档 |
| 归档文档 | `文档/归档/` | 永久（只读） | 不删除、不再更新 |
| 本机分析/审计/探针 | `_本机产物/` | ≤ 30 天（周/月报按需） | 删或压缩；跨机器的结论先脱敏再进 `文档/` |
| 外壳日志 | `12-源码照搬/外壳/server.log*` | `main.js` 4MB 轮转，留 2 份 | 自动轮转 |
| 截图 | `12-源码照搬/外壳/data/captures/` | 7 天 | 删 |
| 探针输出 | `12-源码照搬/外壳/data/<探针名>/` | 30 天 | 删（探针脚本保留在说明里） |
| 临时文件 | `data/temp/`、`_临时/` | 1 天 | 启动时自动清 |
| 引擎升级快照 | `12-源码照搬/外壳/data/engine-*.json` | 最近 3 份 | 删旧 |
| 会话/凭据/工作区 | `12-源码照搬/引擎数据/.dsh/` | 永久、**绝不入库** | 换机器不跟走 |

## 6. 入库 / 不入库边界

**必须入库**：源码、工具脚本、场景模板（`sessionId: "__待填__"`）、`文档/`、编号知识板块、`配图/`、
`模板/`、`12-源码照搬/外壳/data/工具清单.json`。

**绝不入库**：`工作台.json`、`引擎数据/.dsh/.credentials.yaml`、`sessions/`、`storages/`、日志、截图、
缓存、`node_modules/`、`_本机产物/`、本机补丁（`*.optimized.patch.yml`）。

**判据**：`git status --short` 只出现你预期的文件；`node 12-源码照搬\工具\验收.mjs` 第 4 步 `0 命中`。
详细红线见 [AGENTS.md](../AGENTS.md) §7 与 §10。

## 7. 归档流程（SOP，五步）

1. **判定过期**：对照 `README.md` / `AGENTS.md` 的现行口径——被替代、结论作废、只剩历史价值，三者有其一。
2. `git mv <文件> 文档/归档/`（用 `git mv` 保留历史，不要"复制 + 删除"）。
3. **顶部加横幅**（格式固定，结构校验会查 `> ⚠ **已归档`）：

   ```markdown
   > ⚠ **已归档（YYYY-MM-DD）**：本文已移入 `文档/归档/`，只作历史追溯、不再维护；
   > 现行口径见 [文档索引](../README.md) 与 [AGENTS.md](../../AGENTS.md) §9。新结论不要写在这里。
   ```

4. 在 [文档/README.md](README.md) 的「归档」表登记：文件 / 原位置 / 归档日期 / 为什么归档 / 替代文档。
5. 全仓搜旧路径并改引用：`git grep "<旧路径>"` → 跑 `结构校验` + `node 12-源码照搬\工具\验收.mjs`。

> **"复活"规则**：归档文档确需再维护时，先 `git mv` 回 `文档/`、去掉横幅、在索引登记，再改内容——
> **不允许**在 `归档/` 里继续更新（否则"归档 = 只读"就失效了）。

## 8. 检查与责任

| 时机 | 命令 | 判据 |
|---|---|---|
| 每次新增/移动文档后 | `node 12-源码照搬\工具\结构校验.mjs --check` | `✓ 结构与链接全部通过` |
| 每次提交前 | `node 12-源码照搬\工具\验收.mjs` | `✓ 验收通过：6 步全绿` |
| 每月首个工作日 | 清理 `_本机产物/` 超期项、`captures/`、`temp/`；核对根白名单 | 结构校验绿 |
| 每次引擎升级后（AGENTS §6.5） | 同上 + 归档被替代的兼容报告 | 结构校验绿 |

- **pre-commit 已接入**：`.githooks/pre-commit` 先跑结构校验、再跑验收（启用方式见 AGENTS §10.1）。
- **责任**：文档 owner = 最后修改者；跨板块改动必须同步 [AGENTS.md](../AGENTS.md) §9 文档地图与本索引。
- **违反处理**：结构校验红 = 先修再提交；验收红 = 不许提交（判据纪律见 AGENTS §4）。
