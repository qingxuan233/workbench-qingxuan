## 四、标准作业流程（开发五步法）

1. **认领身份与项目确认**：开场 30 秒查表认领身份，**先核会话 cwd**（见 §四之一），读取 `外壳\data\current-project.json` 或运行 `node 工具\当前项目.mjs` 确认当前开发项目，读场景记忆 `§〇 当前交接`；
2. **需求澄清与反例设计**：理清需求与修改权分层，确立目标工程边界，优先确立“反例验收判据”（设计好坏样本比对）；
3. **敏捷开发与工具化沉淀**：执行代码改动，发现跨项目或多轮重复繁琐步骤时，主动抽离为标准化场景工具（放 `工具\` 并自动登记清单）；
4. **验证与反例测试**：执行针对性测试与全量体检，确认无破坏性改动、无编码乱码、反例完全生效；
5. **记忆沉淀与交接闭环**：按规范写回场景私有记忆 `§〇 当前交接` 与 `§五 坑与决策`（≤10行/≤2KB），完成收尾。

### 四之一、新会话的工作区（会话 cwd = 按谁的规范干活）

面板「＋ 新会话」会先问一句“开在哪个工作区”，两个选项对应两类任务：

| 选项 | 会话 cwd | 适用任务 |
|---|---|---|
| **📦 当前项目**（默认） | `代码根\<当前指定项目>` | 对指定项目做深度开发/优化：引擎直接读该项目的 `AGENTS.md` 与目录规范 |
| **🛠 工作台本体** | `仓库根` | 迭代工作台自身（外壳 / 工具 / 场景 / 文档） |

- 两条路**共用同一套场景资产**（技能在 `引擎数据\.dsh\skills`、场景记忆走绝对路径），差别只在"引擎按谁的项目规范干活"；
- 会话建好后会自动在输入框**预填一段开工指令（不自动发送）**，含定位卡 / 场景记忆 / 项目规范确认三步；若没插进去，用「📋 会话 ▾ → 📋 复制开工指令」粘贴；
- 想换项目开发：先切「当前项目」，再开新会话（**不要在旧会话里硬切目录**，cwd 是硬边界）。

## 五、AGENT 约束红线

- ⛔ **跨项目隔离铁律**：操作特定工程时严禁跨目录污染其他工程；严禁将 A 项目的临时文件丢进 B 项目；
- ⛔ **修改权分层铁律**：严禁私自修改 A 级宪法与 C 级核心运行时；严禁修改他人专属记忆；
- ⛔ **临时文件零污染**：临时文件只能落 `<工作区>\_临时\`，严禁写入项目根、盘根、桌面或系统 Temp；
- ⛔ **反例验收铁律**：自证必须配坏样本反例，没有反例证明的断言/工具一律视为无效；
- ⛔ **杜绝无限对话**：跨场景协作与通知一律走工具投递，知悉消息不回复，单任务闭环 ≤3 条；
- ⚠ **会话上下文卫生**：先 grep 后读大文件，大长输出不反复整段粘贴，写回记忆克制精准。
