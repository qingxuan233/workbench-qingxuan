# 清玄的工作台 · 公开模板

一套跑在本机的 **AI 工作台**：5 个场景、每个场景一个 AI 助手、记忆写在本地文件里。
不是聊天工具，是「把日常活分场景交给 AI，让记忆越用越厚」的一套工作方式。

> 只提供**工作台层**（界面 + 场景 + 记忆约定 + 工具）。引擎请自行安装 DSH（DSH 引擎）。

## 装完先跑这两条

```powershell
node 工具\初始化.mjs    # 清掉拷贝带来的残留，把真值重设为本机的
node 工具\体检.mjs      # 15 条断言；刚装好时「未绑会话」算待办，不算错
```

`初始化.mjs` 会删：上一台机器的会话与工作区、运行时日志（里面有引擎 token）、
指向作者机路径的配置；然后重新探测本机引擎、重生成身份卡与索引。
只想看它要动什么用 `--dry`，连登录凭据一起清用 `--hard`。

要部署到另一台机器，看 [部署.md](部署.md)（带走什么、不带走什么、路径为什么不会错）。
**让 AI Agent 自己部署**：用仓库根目录的 [AGENTS.md](../AGENTS.md) —— 机器可执行版（命令 + 期望输出 + 失败分支），
本文给人看，那份给 agent 看。

15 条断言分别回答：数据根与代码口径一不一致、端口是不是只有一个来源、记忆是不是只有一处真源、
会话还在不在库、cwd 还有效吗、面板能不能落到记忆文件、§〇 是不是能直接开工、模板有没有漏本机真值、
文档口径是否唯一、每个 AI 面板是否都绑了会话、身份索引有没有漂移、待确认项有没有人管、
实例清单是否可解析、文本编码会不会乱码、路径基准有没有悬空或重复定义。

**红了就按它给的路径修，别改断言让它变绿。** 判据清单与「什么时候不该用」见
[说明\判据与工具.md](说明/判据与工具.md)。

## 五个场景

| 场景 | 干什么 |
|---|---|
| **命令** | 总览：记忆网络（谁跟谁有关）+ AI |
| **B站** | 看视频 / 理解视频：网页 + AI |
| **自我复盘** | 预览 + 文件库 + AI：周报、复盘、资料 |
| **本地电脑** | 磁盘分区、大户排行、可清理体检、清理台账 |
| **网页AI** | 免费网页版大模型聚合（DeepSeek / 豆包 / 千问 / 智谱 / Kimi）+ AI |

## 跑之前先确认三件事

| 检查 | 要求 | 不满足会怎样 |
|---|---|---|
| Node.js | **18+**（`node -v` 能出版本） | `npm install` 直接报错 |
| DSH 引擎 | 装 DSH 官方版，并把它的 `dsh.cmd` 路径填进 `工作台.json` 的 `engine.cliPath`（`初始化.mjs` 会自动探测写入） | 启动后停在「引擎启动失败 100%」 |
| 端口 | `3083`（引擎）/ `31238`（界面）/ `31239`（网页版 AI 桥）没被别的程序占 | 白屏、一直重试、网页版 AI 不可用 |

> 引擎不是这个仓库自带的——按 DSH 官方方式装好一份即可。
> **引擎装在哪完全由 `工作台.json` 决定**，代码里没有任何写死的盘符；这也意味着旧文档里
> 「把引擎整个搬成 `12-源码照搬\引擎\`」那条路已经作废（`外壳\main.js` 里的 `HARNESS_DIR` 现在没有就为空，
> 不会再拿一个不存在的 `引擎\` 拼路径）。

## 快速开始

```powershell
# 0) 先确认引擎被认出来了（会探测本机 DSH 安装位置并写进 工作台.json）
node 工具\初始化.mjs --dry
#    输出里应有一行「引擎 CLI：…\dsh.cmd」；没有就手工填 工作台.json 的 engine.cliPath

# 1) 安装依赖（只需一次）
cd 外壳
npm install

# 2) 启动（会拉起你自己的 DSH 引擎，端口 3083）
cd ..
双击 启动.vbs

# 3) 给每个带 AI 的场景建会话
node 外壳\scripts\建会话.mjs "命令"
node 外壳\scripts\建会话.mjs "B站"
node 外壳\scripts\建会话.mjs "自我复盘"
node 外壳\scripts\建会话.mjs "本地电脑"
node 外壳\scripts\sessions.mjs --check
```

第一次用之前建议先跑：`node 工具\场景记忆.mjs list`，再用 `init --场景 <名字>` 生成每个场景的身份卡/画像。

## 记忆机制（这套工作台的核心）

```
引擎数据\.dsh\场景记忆\
  命令\场景私有记忆.md    ← 这个场景的记忆（唯一真源）
  命令\_文件索引.md       ← 它有哪些文件
  命令\归档\             ← 交接时旧版挪进这里
  _共享记忆\             ← 多个场景都要用的东西
```

- §〇 当前交接 **≤4 KB**：只写"下一轮要知道的"
- 交接才归档：`node 工具\场景记忆.mjs 交接 --场景 命令`
- 自检：`node 工具\场景记忆.mjs check --场景 命令`
- 跨场景留言：`node 工具\发消息.mjs --to B站 "帮我看下这个"`（纯文件，不发网络请求）

细节看 `说明\记忆约定.md`。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动后「引擎启动失败 100%」 | 引擎路径不对 | 看 `外壳\server.log` 里 `[boot]` 那几行；把装好的 DSH 的 `dsh.cmd` 填进 `工作台.json` 的 `engine.cliPath` |
| 界面白屏 / 一直重试 | 端口被占用（常见：同时开了两个壳） | 关掉另一个实例，或先杀 3083/31238 端口上的进程再启动 |
| `npm install` 卡住/报错 | 网络或 Node 版本太低 | 换国内镜像 `npm config set registry https://registry.npmmirror.com`；Node 升到 18+ |
| 场景标签点开是空的 | 还没给场景建会话 | `node 外壳\scripts\建会话.mjs "命令"`（其它场景同理），再点顶栏 ⟳ |
| 右侧 AI 面板「未连接」 | 没配模型/账号 | 点顶栏 `🧠 模型与提供方` 填 API Key 与模型（保存在本机 `引擎数据\.dsh\profiles\` 下，不入库） |
| 想换引擎位置 | 默认 3083 / 31238 | 改 `外壳\main.js` 顶部 `DSH_PORT` / `SITE_PORT`，两个都改 |
| 引擎装在哪台机器都不同 | 引擎路径**不写死在代码里** | 填 `工作台.json` 的 `engine.cliPath`（或设 `DSH_CMD`）；`node 工具\初始化.mjs` 会自动探测并写入 |

## 打包带走

```powershell
node 工具\封装.mjs --out <盘根>:\发布
```

会生成 `发布包-清玄的工作台-<版本>-<日期>.zip` + `SHA256SUMS`，自动排除 node_modules / 引擎 / 本机数据。

## 二次开发

- 改面板/加场景：看 `外壳\scenarios\*.json` 和 `外壳\renderer\renderers.js`
- 加场景：复制一个 json、改 id/name、配 panels，再同步 `_场景身份索引.md`、跑 `建会话.mjs`
- 改完在 GUI 里点顶栏 ⟳ 刷新面板
- 主进程场景模块：`外壳\main\scenes.js`；改完跑 `node 外壳\scripts\scenes-store.test.mjs`
- 渲染器死代码审计：`node 外壳\scripts\renderer-audit.mjs`
