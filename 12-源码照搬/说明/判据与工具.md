## 一、先分清：你现在这套是「模板」还是「实例」

| | 模板（template） | 实例（instance） |
|---|---|---|
| 给谁 | 要发给别人 / 公开 | 只在自己机器上跑 |
| 里面有什么 | 占位符 `__待填__`、可推导路径 | 真实会话 id、本机路径 |
| 标志文件 | 只有 `工作台.example.json` | 有 `工作台.json`（**不入库**） |
| 判定 | 无 `工作台.json` | 有 `工作台.json` |
| 出包检查 | `发布前检查.mjs` 挡住本机痕迹 | 只挡密钥/IP，本机真值放行 |

**为什么要分**：过去两种身份共用一棵工作树，于是「落地（填真值）」和「出包（去真值）」天生互斥——
填完就跑不了发布检查，不填就跑不起来。现在真值只住在 `工作台.json`，两个身份才算解耦。

```powershell
# 从模板变成实例（会写 工作台.json 并回填场景 json 的 sessionId）
node 工具\实例化.mjs --discover     # 先看会话库有哪些会话、cwd 还有效吗
node 工具\实例化.mjs --apply
```

## 二、六条判据，各有一个命令

| 判据（来自方法论） | 命令 | 绿了意味着 | 什么时候**别**用它 |
|---|---|---|---|
| 全身体检：路径/端口/会话/记忆/§〇/口径/编码 16 条断言 | `node 工具\体检.mjs` | 落地没走样 | 只想改一个文件时——太慢，直接看 diff |
| 怀疑某文件会乱码 / 读不出 | `node 工具\编码检查.mjs` | BOM、换行、代码页三类事故一次报清 | 只改 .js/.md 时——它们没有编码风险 |
| 装好/换机后把残留清干净 | `node 工具\初始化.mjs` | 会话、工作区、日志、作者路径都清了 | 日常改代码时——它会把会话清掉（要留就 `--keep-sessions`） |
| 体检本身有效（反例验收） | `node 工具\体检.mjs --self-test` | 每条断言在坏样本上真会红 | 改判据**之后**必须跑；平时不用 |
| 场景记忆结构 + §〇 可开工 | `node 工具\场景记忆.mjs check --场景 <名>` | 交接写了、能接着干 | 写长文档时——它只管结构，不管内容好坏 |
| 场景 ↔ 面板 ↔ 会话 单一真源 | `node 工具\身份索引.mjs --stamp` | 表是生成的，不是手抄的 | 只改记忆内容时（不动 json 就不用刷） |
| 想动宪法层但没权 | `node 工具\待确认.mjs add …` | 提案留痕，不越权 | 你有 C 档以上的修改权时——直接改，别走提案 |
| 上游变了，先看落在哪一层 | `node 同步上游.mjs` | 宪法层/实例层会被标 ⚠ | 只想看自己改了什么时（它只比 upstream） |
| 出包前扫红线 | `node 工具\发布前检查.mjs` | 没有本机痕迹漏出去 | 日常开发别跑——instance 模式下它本来就是放行的 |

## 三、反例验收：为什么"跑通"不算数

`体检.mjs --self-test` 会临时造**多套**（现 40 项）**故意坏掉**的工作台，要求对应断言必须报红；
再拿一套**好**的，要求全绿。任何一条在坏样本上没报红，就打印 `该断言作废`。
（2026-11-07 实测输出：`自检：40 通过 · 0 失败`。）

这条规矩来自方法论里的失败模式：**「工具跑了、退出码 0」不等于「它在检查」**。
本项目已经踩过两次：

- `场景记忆.mjs` 把会话库拼成 `MEMROOT\..\.dsh\sessions`（双 `.dsh`）⇒ 恒假警告，没人发现；
- `换会话.mjs` 把 `'<工作台>\工具\场景记忆.mjs'` 当真实路径传给 `execFileSync` ⇒ 结构闸每次必然失败，闸形同不存在。

两次都是"代码看起来在检查"。所以现在**任何新判据都要配一个能把它证伪的样本**，写进 `--self-test`。

## 四、§〇 可开工：体量之外的第二道闸

`场景私有记忆.md ≤ 25 KB` 只管"够不够短"，管不住"能不能接着干"。真正的判据是五件事：

1. 上一个人干到哪（不是流水账）；
2. 当前在做什么（有项目表）；
3. 最近改了什么（可追溯）；
4. **下一步是一个动作**（"跟这个场景的 AI 说第一句…"不算，得能直接执行）；
5. **卡点写清在等谁**（没有就写"无"，不能空）。

判据实现只有一份：`体检.mjs` 导出的 `checkKaiGong()`，`场景记忆.mjs check` 直接 import 它。
两处分别实现过一次，结果是"体检绿了、check 还红"，人就开始不信工具了。

## 五、改完东西的固定动作（三步）

```powershell
node 12-源码照搬\工具\体检.mjs            # 1. 全绿
node 12-源码照搬\工具\发布前检查.mjs        # 2. 0 红线（出包时加 --mode template）
git add -A; git commit -m "…"; git push    # 3. 入库
```

`体检` 红了不要"改断言让它绿"——按它给的路径去修；确属判据本身错了，
把坏样本补进 `--self-test` 再改判据（**先能证伪，才允许改**）。

## 六、本次新增的三道闸

| 工具 | 命令 | 作用 | 失败意味着 |
|---|---|---|---|
| 验收 | `node 工具\验收.mjs` | 提交前五步串行；第 4 步按 `git ls-files` 清单跑 template 模式 | 有步骤红，先修再提交 |
| 场景校验 | `node 工具\场景校验.mjs --check` | 文件名/id、面板类型、面板 id 唯一、坐标、sessionId、定位卡、AGENTS 事实段 | 场景 json 或 AGENTS 事实段漂移 |
| 代码红线 | `node 工具\代码红线.mjs --check` | 新文件 ≤800 行；存量只许变短；盘符/sessionId/eval；渲染器登记 | 新增违规或存量增长 |

启用提交前钩子（**保留仓库现有的 `.git/hooks/reference-transaction` 上游闸**）：

```powershell
# ✅ 正确姿势：只补 pre-commit，不动 core.hooksPath
Copy-Item .githooks\pre-commit .git\hooks\pre-commit
```

⛔ **绝不能** `git config core.hooksPath .githooks` —— 一旦设置，Git 只读该目录，
`.git/hooks/reference-transaction` 里的上游闸立即失效（`.githooks/` 里只有 `pre-commit`）。
判据：`git config --get core.hooksPath` 应**无输出**；`.git\hooks` 至少要有
`reference-transaction`、`post-merge`（+ 你抄进去的 `pre-commit`）。

场景事实段与身份索引表都由 `--stamp` 生成，不要手改：

```powershell
node 工具\场景校验.mjs --stamp
```
