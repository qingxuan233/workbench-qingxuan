## 1. 开场 30 秒认领（开工动作）

每次会话启动或进入本场景时，按顺序执行四步：
1. **核验身份**：确认当前会话绑定的场景是 `work-dev`（会话名「工作项目开发」）；
2. **读定位卡**：阅读 `外壳\scenarios\work-dev-context.md`，明确资产范围与边界；
3. **确认/指定当前项目**：
   - 所有开发项目存放在 `代码根\` 下独立文件夹中；
   - 运行 `node 工具\当前项目.mjs` 或读取 `外壳\data\current-project.json` 查验当前指定的是哪个项目；
   - 若需切换开发目标，运行 `node 工具\当前项目.mjs --set <项目名>`（界面右上角面板亦有下拉切换与「设为当前」按钮）；
4. **读场景记忆**：阅读 `引擎数据\.dsh\场景记忆\工作项目开发\场景私有记忆.md` 开头的 `§〇 当前交接`，明确上轮成果、当前进行中项目与卡点。

### 1.1 先认会话落在哪儿（cwd 决定按谁的规范干活）

「＋ 新会话」有两个工作区可选（**会话 cwd = 你选的那个目录**），开场第一件事就是用 `pwd` / 工作目录核对：

| 会话 cwd | 意味着 | 本轮该怎么干 |
|---|---|---|
| `代码根\<项目名>`（**默认**） | 项目工作区：引擎读的是**该项目自己的** `AGENTS.md` / 规范 | 主体任务 = 该项目开发；只在该项目内改动，跨到别的工程一律先申请 |
| `仓库根` | 工作台本体：迭代工作台自身（外壳 / 工具 / 场景） | 改完必须跑四组验收：体检 · 编码检查 · check-gui · sessions --check |

- **两条路共用同一套场景资产**：技能在 `引擎数据\.dsh\skills`、场景记忆走绝对路径，都与 cwd 无关；
- 若会话 cwd 与 `current-project.json` 指定的项目**不一致**：先按 cwd 干活（cwd 是硬边界），并在首轮回复里点明这个差异，由宿主决定是否切会话；
- 需要"给另一个项目开一条干净会话"：不要在本会话里硬切目录，改用面板「＋ 新会话」重选工作区。

## 2. 开发全生命周期与 AGENT 约束边界

### 2.1 项目拓扑与多工程隔离
- **总工程根**：`代码根\` 汇聚所有业务项目；每个子文件夹为一个独立工程；
- **独立隔离**：开发 A 项目时，禁止污染或修改 B 项目代码与配置文件；
- **修改权分层边界（红线纪律）**：
  - **A 级 宪法**（全局铁律 / 标准化规范）：严禁私自改动，规则落盘只认宿主明确指令；
  - **B 级 共享看板**（待办 / 通知 / 索引）：按规范追加，绝不删改他人记录；
  - **C 级 核心运行时**（工作台底层 / 驱动 / 引擎配置）：需经过宿主批准并在 dg-dsh 指导下变更；
  - **D 级 本场景专属**（工作项目代码 / 本场景记忆 / 专属工具）：本场景自主维护，但涉及对外契约变动必须通知关联方；
  - **E 级 别人专属**（其他场景记忆 / 私有资产）：**一个字都不许改**，需求一律走派单。

### 2.2 开发作业流程
1. **需求澄清与设计**：分析任务目标，确定方案架构，梳理目标工程影响面与依赖项；
2. **环境与路径探测先行**：
   - 引用外部命令前先确认环境可用性；
   - 涉及路径配置必须验证实际存在，严禁使用虚构或写死退回路径；
3. **编码与实现**：
   - 遵循 UTF-8 编码无 BOM，BAT/脚本注意换行符（CRLF/LF 规则）；
   - 杜绝长输出刷屏，关键改动保留明确证据；
4. **反例验收（核心方法论）**：
   - 所有断言、体检项与关键业务逻辑必须提供**坏样本反例**；
   - 验证判据：坏样本必须报红、好样本必须全绿；
5. **文档同步与索引登记**：
   - 新建重要文档必须记录到对应目录的 `_文件索引.md`；
   - 严格维护四状态（活 / 常备 / 留档 / 待清）。

## 3. 场景工具沉淀与持续迭代机制

为保证本项目与后续开发项目能够持续优化，本场景内置场景工具孵化机制：

### 3.1 什么时候孵化场景工具
- 某个开发动作在多轮对话中重复出现 ≥2 次（如格式转换、环境探测、自动化体检、数据打包）；
- 某个业务规则容易被遗忘或人工排查耗时（如端口探测、依赖冲突扫描、规范校验）。

### 3.2 场景工具创建标准
1. **一键生成模板**：使用本场景配套脚手架：
   ```powershell
   node 工具\创建场景工具.mjs --name "工具名" --desc "工具用途说明" --tag "开发"
   ```
2. **实现要求**：
   - 脚本必须自带 `--help` 说明与输入参数校验；
   - 涉及改动操作必须提供 `--dry` 预演模式，无 side-effect；
   - 退出码规范：0 成功，1 业务失败，2 参数错误；
   - 自动在 `外壳\data\工具清单.json` 登记，确保工作台顶栏工具面板实时可见。
3. **工具验证**：写好的工具必须在当前环境下真跑验收，并配备正反例测试。

## 4. 完工闭环与交接写回

### 4.1 场景记忆写回纪律
- 只有实质性进展（功能交付、Bug 修复、方案定稿、工具沉淀）才写回；
- **写回预算**：每会话写回 ≤10 行 / ≤2 KB；
- 覆盖更新 `场景私有记忆.md` 的 `## §〇 当前交接` 五小节；
- 长期技术踩坑、架构决策只追加在 `## §五 坑与决策`；
- 体量超标时严格执行“只搬不丢”并保留触发句（搬至 `归档\`）。

### 4.2 跨场景通信
- 给其他场景留言或派单：
  ```powershell
  node 工具\发消息.mjs --to <场景目录名> "【不需要回执·知悉】工作结论与落盘路径"
  ```
- 遵守防无限对话铁律：知悉消息不回复，单任务闭环不超过 3 条消息。
