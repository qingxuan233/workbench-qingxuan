## 五、长期决策与坑

- （只追加）
- **2026-11-02 场景建立：确定「反例先行」与「场景工具沉淀」双引擎机制**
  - 背景：传统 AI Agent 开发容易陷入“单次交付、无工具沉淀、缺乏反例自证”的问题，导致后续开发项目频繁返工。
  - 决策：
    1. 任何核心改动必须设计坏样本反例，反例验证不通过即视为交付不合格；
    2. 将项目开发中出现的重复性操作沉淀为 `工具\*.mjs`，通过工具脚手架标准化生成并自动同步至 `外壳\data\工具清单.json`；
    3. 严格遵循修改权分层，守牢安全红线与临时文件纪律。
- **2026-11-02 路径拓扑澄清：开发项目在 代码根 下，workbench-qingxuan 是其中之一**
  - 背景：开发项目并非全放在工作台子目录，而是并列分布在 `代码根\` 下的各个文件夹中。
  - 决策：场景文件面板根目录直接指向 `代码根\`，方便全局浏览与跨项目预览；定位卡与私有记忆明确拓扑关系，防止多项目开发时上下文与路径混淆。
- **2026-11-02 当前项目指定机制：GUI 与 CLI 双通道对齐**
  - 背景：代码根 下存在十余个工程，作业时必须明确当前上下文属于哪一个工程。
  - 决策：在文件面板内置项目下拉选择器与「★ 设为当前」按钮，同时配备 `工具\当前项目.mjs`，统一读写 `外壳\data\current-project.json`，解决开发项目定位与切换问题。
- **2026-11-02 排障：主进程 kun:file:write 仅接受 D:/E: 绝对路径**
  - 现象：前端面板切换项目写回 `current-project.json` 曾因传相对路径而被 IPC 拦截。
  - 修复：前端显式使用 `window.app.paths.dataDir + '\current-project.json'` 绝对路径写盘，彻底解决跨端状态同步漂移。

## 六、持续迭代与工具库沉淀机制

- **沉淀准则**：
  1. 一类需求在某个或多个项目中出现 ≥2 次，优先封装为命令行工具；
  2. 工具必须具备 `--help`、`--dry`、参数校验与标准退出码；
  3. 沉淀后的工具必须在 `工具清单.json` 登记并在工作台顶栏工具箱展示；
  4. 持续以场景工具反哺整个工作台，优化后续开发流。
